- 摘要：系统支持多人协作审查档案，具备角色权限控制、版本管理、通知机制、审计日志和数据持久性保障。
  - AC-1 支持创建者邀请成员并分配只读/可编辑角色｜Given 用户是档案创建者且已登录系统｜When 创建者在档案详情页点击‘邀请成员’，输入邮箱并选择‘只读’或‘可编辑’角色后提交｜Then 被邀请成员以指定角色加入该档案，角色权限立即生效｜引用「档案创建者可以邀请其他成员加入，被邀请成员分为“只读”和“可编辑”两种角色。」
  - AC-2 只读成员禁止修改需求文本｜Given 用户是以‘只读’角色加入某档案的成员｜When 用户尝试编辑需求文本并保存｜Then 系统拒绝保存，显示提示‘您无权编辑此档案的需求文本’｜引用「只读成员可以查看档案正文、审查结果和导出记录，但不能修改需求文本」

  - AC-4 管理员可无确认删除任意档案｜Given 用户具有管理员权限且已登录系统｜When 管理员在档案列表页点击某档案的‘删除’按钮｜Then 该档案及其全部版本、操作记录、通知记录立即被逻辑删除（软删），无二次确认弹窗｜引用「管理员可以删除任意档案，删除操作不需要二次确认。」

  - TS-3 [exception] 网络延迟导致通知服务超时（>5分钟），但后续重试成功 → 最终所有有效成员在首次触发后≤5分钟内收到通知（允许重试机制补偿），失败重试次数≤3次

## AC-12 自相矛盾的数量约束
- 状态：SUCCESS；类型：None；AC 5 条；测试 4 条
- 摘要：系统需支持所有文件格式上传，但仅允许大小为0字节的文件，且上传响应必须在0秒内完成，失败时无提示。
  - AC-1 支持所有文件格式｜Given 用户准备任意格式的文件（如DOCX、PDF、EXE、ZIP等）｜When 尝试上传该文件｜Then 系统不因文件扩展名或MIME类型拒绝上传｜引用「系统必须支持所有文件格式，包括 DOCX、PDF、EXE 和压缩包」
  - AC-2 仅允许0字节文件上传｜Given 用户准备一个非零字节的文件｜When 提交上传请求｜Then 上传被拒绝，HTTP状态码非2xx，且无前端提示或错误消息｜引用「只允许上传不超过 0 字节的文件」
  - AC-3 0字节文件必须成功上传｜Given 用户准备一个严格为0字节的文件（如空文本文件）｜When 提交上传请求｜Then 返回HTTP 2xx状态码，响应体包含成功标识（如{status: 'success'}）｜引用「只允许上传不超过 0 字节的文件」
  - AC-4 上传响应时间≤0秒｜Given 系统处于正常负载状态，上传0字节文件｜When 发起上传请求并记录起止时间｜Then 端到端响应时间测量值 ≤ 0 秒（即瞬时完成，无可观测延迟）｜引用「上传成功后必须在 0 秒内返回结果」
  - TS-1 [normal] 一个0字节的空BIN文件 → HTTP 200，响应体含{status: 'success'}，耗时0ms
  - TS-2 [boundary] 一个1字节的TXT文件 → HTTP 400或413，空响应体，前端无视觉/交互反馈
  - TS-3 [exception] 一个10MB的PDF文件 → HTTP 413或500，无响应体，前端无提示，服务端日志中不得出现用户可见错误消息
  - TS-4 [boundary] 一个0字节的.EXE文件 → HTTP 200，响应体含{status: 'success'}，耗时0ms
  - 待确认：'0秒内返回结果'是否指服务器处理时间≤0ms，还是包含网络传输？若含传输，则物理上不可行，需澄清定义。；'支持所有文件格式'是否包含校验文件头（magic bytes）以防范扩展名伪造？原文未说明。；当上传0字节文件时，系统是否需持久化存储该文件，或仅校验后即丢弃？
  - 检查问题：引用无法在原文核验：只允许上传不超过 0 字节的文件。失败时不需要任何提示。；引用无法在原文核验：系统必须支持所有文件格式，包括 DOCX、PDF、EXE 和；requirementKind=None，期望 normal
  - 人工判断：把 0 字节/0 秒当作可验收标准，引用拼接不可核验
