# 实验8 运行说明（验收标准集成）

本说明用于本机运行与同学试用。试用时只提供本文件与测试用档案，不替试用者操作。

## 1. 环境

- Windows 10/11，JDK 17，Maven 3.9+，Node.js 20+
- Chrome（试用只需浏览器，不需要开发者工具）
- 后端配置文件 `backend/.env.local`（已在 `.gitignore` 中排除，不要提交）：

```dotenv
AI_MODE=qwen
DASHSCOPE_API_KEY=你的千问Key
QWEN_MODEL=qwen-plus
```

不配置 Key 时后端仍能启动：审查档案可以创建（Mock 模式），但“生成验收标准”会返回
`MODEL_UNAVAILABLE`，这正好可以用来演示 AI 不可用时的处理流程。

## 2. 启动

```powershell
# 后端：读取 backend/.env.local 并启动，端口 8080
cd backend
.\run-local.ps1

# 前端：另开一个窗口，端口 5173
cd frontend
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`。也可以在前端执行 `npm run build` 后用
`npm run preview -- --host 127.0.0.1 --port 5173` 提供静态预览。

## 3. 核心流程（试用任务）

1. 进入「审查档案」，打开任意一份已保存的需求档案。
2. 页面底部「把这份档案变成可验收的测试」区域，点击「生成验收标准」。
3. 观察状态：排队中 → 处理中（显示阶段与已用时间，不显示百分比）。
4. 生成完成后核对：验收标准（Given/When/Then）、测试样例、待确认问题、四项程序检查、逐条原文引用。
5. 需要修改时点「编辑」，改完「保存修改」；确认无误后点「保存到档案」。
6. 刷新页面或重新打开该档案，已保存的验收标准仍可看到。

## 4. 状态与操作

| 状态 | 含义 | 可做的操作 |
| --- | --- | --- |
| 排队中 | 已提交，等待后台线程 | 取消 |
| 处理中 | 正在调用模型或做程序检查，页面显示阶段 | 取消 |
| 已生成 | 结果可用，四项检查可能有未通过项 | 编辑、保存到档案、重新生成、转人工、放弃结果 |
| 生成失败 | 模型超时/失败/输出格式错误 | 重试、规则流程、转人工 |
| 校验未通过 | 引用或覆盖不满足要求 | 编辑、重试、规则流程、转人工 |
| 已拒绝 | 输入不是软件需求，未调用模型 | 转人工、重新生成 |
| 已取消 | 用户取消，迟到结果已丢弃 | 重新生成、规则流程、转人工 |

- 取消是协作式的：排队任务立即取消；处理中的任务会在当前模型调用返回后丢弃结果，页面先显示“正在取消”。
- 刷新页面后按任务编号恢复；超过 30 天保留期的任务会提示重新发起。
- 「规则流程」不调用模型，用规则生成可编辑的占位结果，页面明确标注“非 AI 结果”。
- 「转人工」创建一个可编辑的人工任务，由人填写并保存，原始 AI 结果保留可追溯。

## 5. 数据保存与清理

- 任务：`acceptance_tasks` 表，保存输入快照、状态、阶段、结果、检查、错误、耗时、Token、人工决定；保留 30 天。
- 已确认结果：写入审查档案的 `acceptanceJson`，随档案保存，删除档案时一并删除。
- 运行日志：`backend/logs/acceptance-runs/<runId>.jsonl` 与 `.json`，保留 30 天。
- 清理任务每小时运行一次（`app.integration.cleanup-interval-ms`），只删除已结束且超过保留期的任务。

## 7. 故障演示

```powershell
# 模型不可用：启动时不提供 Key
$env:AI_MODE="qwen"; $env:DASHSCOPE_API_KEY=""
cd backend; .\run-local.ps1

# 模型超时：把读超时设为 1 毫秒
$env:ACCEPTANCE_TIMEOUT_MS="1"
cd backend; .\run-local.ps1
```

两种情况下页面都会给出错误码、当前状态和可选操作（重试 / 规则流程 / 转人工），
用户可以继续完成流程，也可以安全退出。

## 8. 已知限制

- 判分只看程序检查与人工核对，不判断业务语义是否正确；引用逐字匹配不等于需求本身无矛盾。
- 单个档案正文最多 3000 字，超过会拒绝生成，需要先精简档案。
- 取消无法中断已经在途的 HTTP 请求，只能丢弃其结果；任务会多消耗一次模型调用。
- 同一浏览器同一档案只保留最近一次任务编号用于刷新恢复，更早任务从“本档案任务”列表进入。
- 未实现登录与多用户隔离，所有档案在同一本地数据库中。
